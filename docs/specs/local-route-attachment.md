## Problem Statement

用户希望将已经真实就绪的本机模型自动挂载到当前 BurnCloud 实例的 Router，随后由 Router 按模型能力和所选策略分配请求。首版已确认由 Server 启动配置提供端点清单，暂不接入客户端运行中新就绪模型的自动挂载。模型异常、容量耗尽或存活信息失效时，节点必须停止接收新的分配，不能仅因为数据库仍有一条启用记录就继续接单。

项目已经存在本机挂载公共契约、复用现有供给存储的适配器及部分挂载协调逻辑，但这些基础不能等同于已经完成生产环境中的自动接线、持续心跳、真实并发容量控制和实际派发前的可用性检查。界面中的模拟就绪状态、通用服务健康响应和固定 ID 的测试替身也不能证明模型已经真实可用。

用户同时要求模型匹配前提下的均衡、稳定优先、价格优先三种策略。目标是在现有框架内完成闭环，尽量少改 crate、少写代码，而不是重新建立 Router、节点注册体系或计费体系。

## Solution

复用当前实例的 Router、供给存储及现有本机挂载接口。首版由 Server 读取启动配置中的已真实就绪端点清单，每项仅包含 model 与 base_url；校验端点和模型别名后调用现有挂载接口，获得实际生成的挂载 ID。Server 生命周期内的管理任务持续检查对应模型服务，Router 结合健康状态、有效心跳及独立并发槽决定是否允许新分配。启动配置和模型列表成功都不能代替模型已经真实就绪的前提。

请求先满足模型、用户组及可用性要求，再选择最高可用的管理员优先级档。均衡、稳定优先、价格优先各自筛出候选集合，共用按管理员权重选择目标的逻辑。新策略不被会话亲和重新置顶覆盖；显式配置的旧策略保留原有亲和行为，但不能绕过本机挂载的共同准入条件。

本规格描述完整目标，不把 Ticket 01 的生命周期实现当作整套功能已经完成。启动配置格式、首检时序及重启规则已确认；其他运行阈值、恢复细节、价格比较口径、容量配置边界和故障分类仍保留待决。全部后续推荐及源码依据集中在 docs/specs/local-route-attachment-implementation-basis.md，未经确认不作为编码常量。

## User Stories

1. 作为本机模型使用者，我希望 Server 启动时按配置清单校验并挂载已真实就绪的模型，以便通过已有请求入口使用它，而不依赖客户端运行中的就绪事件。
2. 作为挂载调用方，我希望挂载成功后得到实际生成的挂载 ID，以便准确隔离或摘除同一挂载。
3. 作为现有接口调用方，我希望输入仍只有模型别名和服务地址，以便不因心跳、容量或策略增加而修改既有输入契约。
4. 作为请求使用者，我希望 Router 只选择匹配请求模型能力的节点，以便不会因为负载或价格改用不匹配的模型。
5. 作为项目维护者，我希望本机挂载复用现有 Router 和供给存储，以便不维护第二套路由事实来源。
6. 作为用户组管理员，我希望请求继承所属用户组的一种路由策略，以便复用现有配置入口而不新增客户端开关。
7. 作为未配置路由策略的用户，我希望默认使用均衡策略，以便无需额外设置即可分摊请求。
8. 作为用户组管理员，我希望均衡策略按管理员权重分配请求，以便配置相对分配比例。
9. 作为稳定性优先的用户，我希望同档可用候选中健康评分最高的节点优先接单，以便依据已有运行表现选择目标。
10. 作为价格优先的用户，我希望在同档可用且报价可比较的候选中优先选择最低价者，以便按约定的报价口径择优。
11. 作为价格优先的用户，我希望并列最低价节点按管理员权重分摊请求，以便同价时也不会始终集中到一个节点。
12. 作为计费规则维护者，我希望缺失报价和本机运行都不自动等于免费，以便不绕过已有计费校验。
13. 作为管理员，我希望较高优先级档全部不可用时能使用较低档的可用节点，以便已有备用供给不会被忽略。
14. 作为新策略使用者，我希望会话亲和不能替换策略选出的目标，以便均衡、稳定择优和价格择优真正生效。
15. 作为显式配置旧策略的用户，我希望原有亲和选择能力被保留，以便不无故删除既有行为。
16. 作为本机节点维护者，我希望每个挂载独立计算并发容量，以便不同挂载不会误用同一个全局槽位。
17. 作为部署者，我希望一个启动配置统一设置本机挂载并发上限、默认每个挂载为 1，以便保持首版配置简单。
18. 作为流式推理使用者，我希望整个响应流期间持续占用并发槽，以便收到响应头后不会过早放入新请求。
19. 作为请求使用者，我希望容量耗尽的节点不再接收新分配，以便不会因路由层超额分配影响运行稳定性。
20. 作为节点维护者，我希望心跳来自真实模型服务的检查，以便不能靠单纯刷新时间戳维持假可用状态。
21. 作为客户端使用者，我希望关闭或离开聊天界面不会被当成模型失联证据，以便界面状态不决定节点存活。
22. 作为服务使用者，我希望管理任务停止更新后 Router 仍能根据心跳失效拒绝该挂载，以便停派不依赖后台清理及时运行。
23. 作为节点维护者，我希望连接失败、探测超时或模型别名消失能够进入可用性判断，以便失效端点不会继续接单。
24. 作为服务使用者，我希望真实推理暴露的模型故障能反馈给路由可用性判断，以便模型列表成功不能掩盖推理故障。
25. 作为本机模型使用者，我希望后台不周期性额外发送测试推理请求，以便健康维护不会引入额外推理负载。
26. 作为挂载调用方，我希望隔离成功后该挂载不再获得新的请求分配，以便可以可靠地进行后续恢复或清理。
27. 作为挂载调用方，我希望摘除通过现有结果与错误类型报告成功或失败，以便调用方能处理可恢复错误。
28. 作为维护者，我希望注册或隔离失败不会被包装成成功，也不会留下互相矛盾的供给和能力状态，以便错误可追踪、可重试处理。
29. 作为验收者，我希望使用真实 Router、实际生成的 ID 和可观察的上游请求验证行为，以便不把测试替身结果当作生产接通证据。
30. 作为验收者，我希望并发请求不能突破每个挂载的接单上限，以便容量控制在竞争条件下仍然成立。
31. 作为项目维护者，我希望修改集中在必要的现有模块，并尽量复用已有公开能力，以便控制代码和工作区范围。
32. 作为公共接口调用方，我希望不安全或无效的外部参数按契约返回错误而不是造成非预期崩溃，以便接口具有可验证的安全边界。
33. 作为后续开发者，我希望公共接口文档、README、独立测试和回归测试与实现同步，以便行为能够维护和复查。
34. 作为评审者，我希望已确认约束、推荐草案与真实测试记录明确区分，以便不会把未决方案或样例数值误认为已验收事实。

## Implementation Decisions

### 1. 范围与最小改动目标

- 仅处理当前 BurnCloud 实例内的本机路由挂载，不增加跨机器注册或远程心跳上报协议。
- 复用现有 Router 与供给存储，不增加第二个 ModelRouter、独立本机路由表或新的供给持久化所有者。
- 最小实现目标是把改动集中在现有 Router 与 Server 生命周期／挂载协调模块；供给、计费、Node 和客户端能力优先复用。
- 首版已确认采用 Server 启动配置接线，不包含客户端运行中新就绪模型的自动挂载；优先将业务改动控制在 Router 与 Server。若实际落地需要其他 crate 的必要改动，应明确原因及最小范围，不能将两个 crate 视为已验证的充分条件，也不可用 Fake 接线替代真实完成。
- 不新增 workspace 成员或通用扩展框架。不授权跨域直接 SQL、新建节点报价表或为未来用途提前增加抽象。
- 现有挂载适配器通过供给所有者的公开能力创建、隔离和删除 Channel；继续遵守这条所有权边界。

### 2. 保持现有公共契约

| 契约 | 必须保持的内容 |
|---|---|
| LocalRouteAttachment | 公开输入字段仍为 model 和 base_url，二者均为 String。心跳、容量、价格、策略不是该输入结构的既有字段，也不在本轮向其中新增。 |
| LocalRouteAttachmentId | 保持现有公开 i32 新类型，身份取自实际创建结果，不把样例数值写死。 |
| LocalRouteAttacher | 保持现有异步挂载接口以及 Send、Sync 约束。 |
| attach | 接收 LocalRouteAttachment；返回以 LocalRouteAttachmentId 为成功值、LocalRouteAttachmentError 为错误的 Result。 |
| quarantine | 接收 LocalRouteAttachmentId；返回以单元值为成功值、LocalRouteAttachmentError 为错误的 Result。成功表示保留挂载身份并停止新分配。 |
| detach | 接收 LocalRouteAttachmentId；返回以单元值为成功值、LocalRouteAttachmentError 为错误的 Result。 |
| LocalRouteAttachmentError | 保持 AttachFailed 和 DetachFailed 两个携带 String 的变体；现有隔离失败使用 DetachFailed，不新增错误变体。 |

新增函数、方法和字段默认私有。若确需新增跨模块公开能力，须先明确其公开契约，不将本规格视作无限扩大可见性的授权。未明确变更的既有公共可见性保持不变。

### 3. 真实就绪、模型能力与地址

- 输入的本机模型必须已经真实就绪；模型下载、安装及完整部署系统不是本功能的前置实现任务。
- 原 D08 已于 2026-11-04 确认：由 Server 启动配置提供已就绪端点清单，每项仅表达现有 model 与 base_url；Server 校验端点和模型别名后调用既有 LocalRouteAttacher::attach，并在自身生命周期中持续管理挂载。
- 首版不接入客户端运行中新就绪模型的自动挂载，不新增客户端 UI、公开注册 HTTP API、模型安装器或 workspace 成员。启动配置不是独立路由表，挂载身份及能力仍复用现有供给存储。
- D07 的端点协议范围已于 2026-11-04 确认：首版仅接入无需上游 API Key 的本机 OpenAI 兼容服务；这不取消 BurnCloud 请求入口既有的认证、授权或计费校验。
- base_url 使用 HTTP(S) 回环 IP 的服务根地址，例如 `http://127.0.0.1:8080`；不接受域名、非回环地址、/v1 等路径前缀、URL 内用户名密码、查询参数或片段。末尾斜线可统一去除；本机端点探测与推理均不跟随重定向。
- 存活探测请求同一根地址的 /v1/models，在有效成功响应中精确匹配 data[].id 与配置 model，不自动改写别名或注册其他模型。本机聊天推理最终请求同一服务的 /v1/chat/completions，不能让探测与推理使用不一致的根地址或路径语义；不因此修改非本机供给的既有地址约定。
- D07 的启动处理已确认：未配置本机挂载或配置为空清单时，Server 正常启动且不创建本机挂载；配置格式、必填字段或地址不合法时明确报错并拒绝启动，完成整份配置校验后才执行挂载。
- 合法清单中的单个端点首检失败时，该项不挂载、不接请求并记录失败，不阻止 Server 和其他可用供给继续服务；由同一管理任务继续探测，通过后再尝试首次挂载。该重试仅适用于清单中尚未成功挂载且首检失败的项，不用于自动解除隔离或发现运行中新端点。
- 上述确认不表示启动接线或协议校验已经实现。配置项名称与格式、故障分类、探测周期和重启残留规则仍需设计确认；已确认的模型字符串合法域、重复操作结果与持久化失败处理不表示适配器已经实现；模型列表成功仍不证明推理成功。
- 挂载通过现有供给与能力机制登记模型别名及对应服务地址，Router 必须能经既有请求路径选择并实际访问该地址。
- 持续检查直接访问对应模型服务，并核对其模型列表仍包含挂载别名。别名对应的模型能力和地址必须与被检查、被派发的挂载一致。
- 模型列表成功只能证明端点可达、模型声明存在，不能作为推理成功证明，也不能把一个别名的挂载擅自扩展为该端点全部模型的注册。

#### 启动配置、首检时序与重启残留（2026-11-05 已确认）

- 环境变量 `BURNCLOUD_LOCAL_ROUTE_ATTACHMENTS` 为 JSON 数组；每项仅有 `model` 与 `base_url`。整份配置校验完成前不进行任何端点探测或挂载。
- 首次立即探测，首检失败后每 5 秒复探，单次超时 2 秒；attach 失败后停止该项自动挂载，不重试数据库写入。5 秒／2 秒此次仅确认为首次挂载时序，未确认运行中心跳的 15 秒有效期或两次成功恢复。
- 停止时终止管理任务，禁止迟到结果发布挂载。重启不自动收养、删除或恢复旧挂载，残留继续禁派；核对并显式 detach 后才能重新挂载，无残留项正常处理。
- 残留的人工清理不解除 D05 的本次自动尝试停止状态；同次运行不会因清理完毕自动重试。显式管理沿用 Rust 接口，不新增 HTTP／CLI 入口。
- 代价：有残留时重启不能自动恢复本机接单，需要人工介入。技术实现必须同时覆盖 Router 禁派及管理任务退出，不能只取消网络探测。

#### 挂载目标与身份边界（D05 已确认）

2026-11-04 用户已确认以下身份规则；这是目标契约，不表示现有适配器已经具备重复挂载判定。

- 当前实例内，用模型名与规范化服务根地址共同识别同一挂载目标；管理操作仍通过 LocalRouteAttachmentId 指向具体挂载，不以模型名单独作为身份。
- 模型名精确匹配，不自动修改大小写或模型别名；模型字符串合法域按下方 D07 约定校验。地址在满足已确认端点约定的前提下按协议、回环 IP 和有效端口比较，末尾斜线及显式／省略默认端口不产生不同身份；不同协议、不同有效端口或不同回环 IP 不合并。
- 同一挂载目标最多保留一个尚未摘除的挂载。并发或重复 attach 不得创建多份供给或增加并发额度；故障与隔离不释放该目标身份，重复注册不能绕过停派。
- 同一模型、不同地址是不同挂载目标，允许供均衡等策略选择；同一地址、不同模型也分别挂载，各挂载 ID 独立计量容量。首版不增加端点级共享容量，也不把每挂载上限宣称为该物理端点全部模型的总上限。
- 不增加原地更新接口。改变模型名或地址不会改写旧挂载 ID 的目标；若意图替换旧挂载，由调用方先 detach 旧挂载，再 attach 新挂载。

#### 挂载管理操作结果（D05 已确认）

2026-11-05 用户已确认以下结果规则。它们是目标契约，不表示当前适配器已经实现去重、归属检查或完整的失败处理；持久化失败处理见下一节。

- 对同一模型名与规范化根地址的重复 attach，若现有挂载仍通过健康、心跳和隔离状态门禁，则返回该现有挂载的 ID；即使当前容量已满，也不新建供给、不增加并发额度、不重置心跳或健康状态。
- 若同一目标已有挂载但处于隔离、已知模型故障或心跳失效状态，重复 attach 返回 AttachFailed，保留原挂载及其停派状态；重复注册不能解除隔离或恢复接单。
- 对仍存在的本机挂载重复 quarantine，返回 Ok(()) 并继续保持隔离；对正数但不存在或已摘除的 ID 调用 quarantine，返回 DetachFailed。
- 对正数但不存在或已摘除的 ID 调用 detach，返回 Ok(())，表示目标当前已不存在；该成功不证明它曾经注册成功。数据库查询或写入失败必须返回 DetachFailed，不能按“不存在”处理。
- 对现存但不属于本机挂载的 ID，或小于等于 0 的 ID，quarantine 与 detach 均返回 DetachFailed，不能修改其他供给。数据库失败、权限失败或事务失败也不得伪装成成功。
- 成功 detach 后再次挂载同一目标，必须使用实际新生成的 ID，不复用旧 ID；旧 ID 的后续操作不能影响新挂载。模型名或地址变化不通过原地更新完成，替换仍先 detach 旧挂载再 attach 新挂载。

#### attach 持久化失败处理（D05 已确认）

2026-11-05 用户已确认以下规则，D05 的剩余决策据此收敛；这是目标契约，不表示已实现或已通过故障验证。

- 首版不新增数据库写入自动重试机制。attach 持久化失败返回 AttachFailed，不吞错，也不在接口内部循环重试。
- 启动管理任务记录该项错误，并停止该配置项的自动挂载尝试；不影响其他正常供给。数据库恢复后，该失败项不会自行重新挂载，这是首版为减少代码和恢复状态分支而接受的代价。
- 提交结果不确定时，不把该新挂载视为成功，也不向它授予派发许可；由调用方核对后显式重试，仍遵守已确认的挂载目标身份与重复操作规则，不创建重复供给、不扩容或解除停派。
- 端点首检失败后由同一管理任务继续探测的规则不变；首检失败与持久化失败分开处理，不能借后续探测重新触发持久化失败项的自动挂载。

本决定不扩展 LocalRouteAttachment 输入或 LocalRouteAttachmentError 的两个错误变体。D06 另按本轮独立确认的保守重启规则执行，不从 D05 推导自动恢复。

#### 模型字符串合法域（D07 已确认）

2026-11-05 用户已确认：本机挂载的 model 必须作为一个原样、单一的模型别名贯穿能力登记、Router 匹配和端点探测；非法值通过 AttachFailed 返回，不静默改写后继续挂载。

- model 非空，且必须满足 `model == model.trim()`；首尾 Unicode 空白直接拒绝，不自动 trim 后改名。
- 禁止英文逗号 `,`，因为现有供给能力生成会把它解释为多个模型的分隔符；不因此禁止其他普通标点。
- 禁止控制字符，以 Rust `char::is_control()` 判定，包括换行和制表符；不额外禁止内部普通空格。
- 保留原始大小写和 Unicode，不做大小写折叠、Unicode 归一化或未经确认的 ASCII 白名单限制；冒号不在本次禁止列表中。
- 长度为 1–34 个 Unicode 标量值，使用 Rust `chars().count()` 计量，不按 UTF-8 字节数或视觉字形数计量。首版采用 34 上限以兼容现有适配器的 16 字符名称前缀 `BurnCloud Node: ` 和 PostgreSQL `channel_providers.name VARCHAR(50)`；不修改数据库字段，也不把该限制扩展到非本机供给。
- 该校验只约束本机挂载入口，不修改既有非本机供给对多模型字符串的逗号拆分和空白处理语义，也不统一 trim Router 的请求模型字段。

`LocalRouteAttachment` 的两个字段保持不变；model 非法时仍使用既有 `LocalRouteAttachmentError::AttachFailed(String)`，不新增错误变体。启动清单中的非法 model 同样按已确认的整份配置校验规则拒绝启动，不先挂载其他项。

合法本机别名必须原样贯穿候选匹配、上游请求、运行反馈和计费；保留 Gemini 原生路径方法后缀语义，不通过禁止冒号或截断别名规避兼容。Ticket 01 已修复外层模型名副本的统一冒号截断，已有受控测试记录，见 0001 任务报告；真实模型及完整 Server 装配仍未验收。

### 4. 心跳与运行状态职责

- 本机挂载管理任务跟随当前 Server 生命周期运行，持续检查真实模型端点并更新心跳和运行状态。
- 不以聊天界面在线与否作为存活依据；不能将通用 Server 健康响应或无真实探测的时间戳刷新当作有效挂载心跳。
- 使用轻量端点探测与真实推理结果反馈，不周期性额外发起测试推理。
- 连接失败、超时、模型别名消失和真实推理暴露的模型故障均须参与停派判断；故障分类、阈值与恢复细节见待决项。
- 即使管理任务停止更新，Router 也必须能独立依据心跳失效拒绝新分配。
- 注册适配器、管理任务和实际 Router 派发路径必须共享一致的挂载可用性事实；新增一份未接入派发路径的状态不算完成。

### 5. 共同准入条件与隔离保证

- 新分配必须满足模型匹配、用户组路由条件、节点健康、心跳有效以及可用容量大于零。
- 管理员优先级、权重、价格或会话亲和都不能绕过准入条件。
- 隔离成功后不能继续依赖旧候选缓存向该挂载分配新的请求；不能仅证明下一次数据库查询已排除节点就宣称实际停派已经成立。
- 并发容量取得和可用性判定必须对真实派发有效，不能以有竞争窗口的旧计数或候选快照替代保证。
#### 派发许可、在途请求与错误响应（D03 已确认）

2026-11-04 用户已确认以下规则。确认仅覆盖 D03，不表示已经实现或通过测试；其他待决项仍按各自状态处理。

**许可与在途边界：**

1. 进入候选列表、策略选中或命中亲和均不等于获得派发许可。每次向本机上游发起尝试前，复查该挂载当前可用性并占用一个并发槽；这一步与隔离、摘除的禁止新许可效果具有明确的并发先后关系，不能用独立的旧快照判断替代。
2. quarantine 或 detach 成功返回后，不再给该挂载授予新的派发许可，包括此前只进入候选列表的请求。成功返回前已取得许可并占槽的那一次尝试允许继续，不因本次隔离或摘除主动截断；正常超时、取消或真实上游失败仍可结束它。
3. 停派边界以“许可授予”为准，不以实际发出第一个网络字节为准。因此先获许可的尝试即使随后才被调度到发送，也属于允许继续的在途尝试；不承诺隔离返回后绝无任何网络发送。一个许可仅用于一次尝试，重试或切换目标必须重新检查并取得许可，不能借旧许可继续接单。
4. 流式响应在整个流处理生命周期内占槽，不能在收到响应头或返回流对象时释放。普通响应完成，以及错误、超时、取消等真正结束处理的路径均释放对应槽位；若后台仍在处理上游流，不把前端断开误当作该处理已经结束。不保证已异常或失联的模型一定成功返回。
5. 容量为零只跳过该挂载，不记为模型故障、不隔离、不删除；槽位释放且其他准入条件满足后可再次获得许可。允许按既有请求重试预算及已确认的优先级规则寻找其他候选；没有可用候选则返回错误，不新增等待队列或等待容量恢复的循环。

**请求侧错误响应：**

| 情况 | 已确认响应与兼容边界 |
|---|---|
| 已识别本机准入拒绝，候选耗尽且本请求尚未发起任何上游尝试 | 复用调度器的 HTTP 503：error.type 为 service_unavailable，error.code 为 no_available_channels，rejected_by 为 scheduler；沿用 X-Rejected-By: scheduler 与 Retry-After: 60。该数值只是已有客户端退避提示，不是心跳有效期或恢复时间承诺。 |
| 供给查询本身没有匹配路由，且未识别到本机准入拒绝 | 保留既有空路由路径：通常为 HTTP 404、no_available_channel，已有准备中响应仍优先适用。不为了统一状态码新增已删除路由的记录或第二套路由事实来源。 |
| 隔离／摘除后的新查询已看不到候选，也未识别到本机准入拒绝 | 同样沿用上述空路由路径；不能宣称所有隔离／摘除后的无路由情况都会变成 503。两种响应都必须保证不再向该挂载分配新许可。 |
| 已实际尝试上游后全部失败，或请求重试预算到期 | 保留现有失败／超时分支，分别沿用 HTTP 502、all_upstreams_failed 或既有 HTTP 504、retry_deadline_exceeded；不能因后来某个候选被本机门禁拒绝而掩盖已发生的上游失败。已经开始流式响应的错误也不能改写为新的 HTTP 状态。 |
| 既有认证、授权、计费、纯速率预算等拒绝 | 保持现有各自处理，不统一改成上述本机准入 503；本决定不涉及 D04 价格不可比较时的最终响应。 |

上述 HTTP 错误属于请求派发结果；LocalRouteAttacher 的 attach、quarantine、detach 仍使用既有返回类型与 AttachFailed／DetachFailed 两个错误变体，不新增“容量不足”管理接口错误。

**并发验收例（已确认行为，非实测记录）：**A 已取得许可并占槽，B 仅保留候选快照；随后 quarantine 返回成功。A 的那一次尝试可继续直至完成或正常终止，B 不得再取得该挂载许可。A 若需要重试，也必须重新准入，不能复用旧许可绕过隔离。流式 A 尚未结束时槽位仍被占用。

D03 的确认不批准探测阈值或故障恢复；这些内容仍分别属于 D01、D02 等待决项。D05 的身份、操作结果与持久化失败处理已确认，重启残留现按已确认 D06 保守处理。现有速率预算不是并发槽，也不代表本节已完成实现。

### 6. 并发容量

- 每个挂载 ID 独立计算可用容量，等于该挂载最大并发数减去当前在途请求数；同一地址的不同模型也独立计量，不增加端点级共享容量。同一挂载目标不能通过重复 attach 增加 ID 或额度。
- 容量不是机器剩余 CPU、内存、显存，也不是 RPM／TPM 分钟速率预算。
- 一个 Router 启动配置统一指定本机挂载的并发上限，默认每个挂载为 1。统一的是上限值，不是所有挂载共享一个槽。
- 配置改变后重启生效；首版不做按模型覆盖或热更新，名称及合法域的集中推荐为实现依据 R03，尚未批准。
- 流式请求占槽覆盖整个响应流，不能在收到响应头时释放。容量为零时不得新增分配。
- 完成、取消、失败等结束路径不得遗留槽位占用；后台仍在处理响应流时不能仅因前端断开提前释放。隔离或摘除不主动中断已有许可的那一次尝试，满载只跳过、不判故障、不排队，按已确认 D03 执行。

### 7. 策略配置与管理员优先级

- 均衡、稳定优先、价格优先为三个独立策略，每次请求继承所属用户组的一种策略，不是三级固定排序链。
- 复用 SCHEDULER_POLICIES 的按用户组配置入口，不新增客户端切换界面或请求参数。
- 未配置策略时的首版目标行为为均衡。这是待实现目标，不是对当前默认 Passthrough 行为的描述。
- 在满足共同准入条件的候选中优先使用最高可用管理员优先级档；高档全部不可用时允许降到下一档，不因降档放宽模型或可用性要求。
- 管理员优先级决定档位；管理员权重只在最终参与分摊的候选集合中决定相对选择概率。

### 8. 共用选择逻辑

| 策略 | 在最高可用管理员优先级档内保留的候选 |
|---|---|
| 均衡 | 全部满足共同准入条件的节点。 |
| 稳定优先 | 现有运行健康评分最高的节点。 |
| 价格优先 | 具有最低有效、可比较报价的节点；比较口径尚待确认。 |

筛选后共用一个内部选择函数：仅一个候选时直接选择，多个候选时按管理员 weight 加权随机，权重相同则等概率。不为三种策略复制三套选择算法，不额外维护轮询进度。

稳定优先复用已有成功／失败、延迟等运行健康指标，不新增评分系统；它评价服务运行表现而非模型回答质量。均衡表示概率分摊，不保证逐次交替或短期请求次数严格符合权重比例。

### 9. 价格来源与同价处理

- 复用既有按模型与 region 查询的报价，不增加按挂载 ID 或节点单独报价的表、配置或输入字段。
- 在最高可用管理员优先级档内，并列最低价的可调度候选按统一权重随机逻辑分摊；满载或不满足其他准入条件的节点不能参与。
- 缺失报价不表示零价格，本机模型不默认免费，也不绕过既有计费校验。
- 同模型、同 region 的节点可能使用相同报价；此时不能宣称已经区分其真实运行成本。
- 输入价与输出价的比较口径、币种不可比较时的处理、明确零报价及全部缺价时的行为仍是待决项。最近提出的参考报价方案尚未被确认，不能写成已经批准的算法。

### 10. 会话亲和与兼容性

- 三种新策略不再被会话亲和重排候选或替换所选目标。
- 不全局删除原有会话亲和能力；显式配置的旧策略保留其原有亲和选择行为。
- 未配置策略采用新默认均衡，不等同于显式选择旧策略。
- 保留旧策略亲和不意味着本机挂载可以绕过共同准入门禁。针对既有非本机供给的完整兼容范围另列待决项，不能静默扩大改动范围。

### 11. 工程约束

- 公共接口按项目规则进行参数安全验证；不得通过给所有私有函数重复增加参数校验来扩大实现。

### 真实模型验收场景

使用模型别名 `qwen-4b`、服务地址 `http://127.0.0.1:8080` 作为场景值，前提是该别名已经在真实模型服务中就绪，且请求、路由授权及计费所需前置条件实际满足。

attach 返回的 ID 以真实结果为准。只有实际生成 ID 为 42 时，才可以把 42 用于随后隔离和摘除；42 不是预先写死的目标，也不是已经存在的注册记录。

至少观察一次真实模型请求经 Router 到达挂载服务并获得实际响应，再验证隔离成功后的新请求不再发往该挂载。受控上游、Fake Node 或界面显示 Ready 都不能单独替代这一记录。

本规格中的地址、模型名和 ID 是验收场景描述，不是本次执行或通过记录。

## Out of Scope

- 新增第二个 Router、独立本机路由表、跨机器节点注册、云端接入或远程心跳协议。
- 将模型下载、安装、硬件部署和完整进程编排系统全部纳入本功能；本契约以前置真实就绪为起点。
- 首版接入客户端运行中新就绪模型的自动挂载，或为挂载新增客户端 UI、公开注册 HTTP API；本轮仅采用已确认的 Server 启动配置触发。
- 为本机挂载新增上游凭证输入、接入非回环或域名端点、支持路径前缀或重定向；不借此更改既有非本机供给的地址及鉴权规则。
- 新增客户端策略切换界面、每次请求的策略参数或对 LocalRouteAttachment 输入字段的扩展。
- 按模型覆盖并发上限、配置热更新，或把 CPU、内存、显存剩余量自动换算成接单容量。
- 把 RPM／TPM 速率预算当作并发槽，或者为每次心跳重建满额预算冒充容量更新。
- 为容量恢复新增等待队列或等待容量恢复的请求循环；正常候选切换仍遵守现有请求重试预算和已确认优先级规则。
- 周期性额外测试推理、新的健康评分系统、回答质量评分或基于新模型的调度预测。
- 新建节点独立报价体系、假定本机模型免费、承诺选择实际运行成本最低的机器。
- 为三种策略增加互相复制的选择实现、新 workspace 成员、通用插件体系或超出本功能所需的解耦。
- 借此全面重写现有旧策略、修复所有历史调度问题或扩大 CI；只处理实现本规格所必需的兼容与缺陷。
- 本次规格整理不包含业务代码实现、真实模型部署、代码提交、PR 创建或测试通过声明。

#### D08：首版生产触发范围已确认

本轮定点核查确认：正常 Server 创建流程启动了 NodeRuntime，但该生命周期入口目前只设置启动标记和日志；生产挂载适配器的构造调用出现在现有集成测试中，正常启动尚未接入。现有挂载协调逻辑可以在就绪后执行挂载，但其存在不证明生产调用链已成立。客户端 LocalBackend 的模型状态仍来自内置目录和示例数据，不能直接作为真实模型就绪来源。

**已确认的最小接线范围**：由 Server 启动配置提供已真实就绪的本机端点清单，每项只表达现有的 model 与 base_url；Server 按已确认的端点协议和启动处理调用既有 LocalRouteAttacher，并在 Server 生命周期中持续管理挂载。不增加客户端 UI、公开注册 HTTP API、模型安装器或新的 workspace 成员。配置名称与 JSON 数组格式现已确认；配置边角、运行故障分类等剩余内容见集中实现依据。

本首版仅自动挂载启动配置中的已就绪端点，暂不接入客户端运行中新就绪模型的自动挂载。这是用户明确接受的首版范围，不是把客户端事件接线冒充为已经完成；如以后纳入该能力，须另行确认真实事件来源及最小改动范围。

配置清单不是独立路由表：正式挂载身份、模型能力与地址仍进入现有供给存储；是否可调度仍由真实 Router 的共同准入门禁决定。端点模型列表成功也不证明推理成功，真实模型推理验收仍不可省略。

### 代码核查对实现的提醒

既有 scheduler 的价格因子以输入价和输出价的合计为基础，但旧综合评分会混合其他因子与权重，且其缺价默认值、换汇失败回退和数值归一化不能直接证明“最低有效且可比较报价”。新价格优先不能仅改旧综合评分的权重就宣称符合本规格；最终应以确认后的比较口径验证外部结果。

既有健康未知时的默认行为、最高优先级候选预筛选、亲和置顶及早于派发的可用性快照，也都需要在真实路径中核对。数据库挂载成功不等于完整可调度闭环已经实现。
