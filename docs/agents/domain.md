# Domain Docs

## 布局

采用 single-context：整个 Rust workspace 共用领域文档。

- 根目录 `GLOSSARY.md`：已确认的领域术语。
- 根目录 `docs/adr/`：架构决策记录，采用 `0001-<主题>.md` 的编号形式。

## 探索前的读取规则

1. 阅读根目录的 `GLOSSARY.md`。
2. 阅读 `docs/adr/` 中与当前工作相关的决策。
3. 文件或目录不存在时，安静继续，不将缺失视为阻塞，也不建议提前创建占位文件。
4. 由 `/domain-modeling` 在术语或决策实际确认后按需创建和维护这些文档。

## 使用领域术语

Issue 标题、设计方案、代码命名和测试名称应使用词汇表定义的术语，
避免替换成词汇表明确排除的近义词。

需要的概念尚未收录时，先检查是否误用了项目术语；
确有缺口时，交由 `/domain-modeling` 澄清并记录，不自行编造定义。

## 显式指出决策冲突

方案与既有 ADR 冲突时，指出对应 ADR 和重新讨论的理由，
不得静默覆盖既有决策。
