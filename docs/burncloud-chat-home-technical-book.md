## 本轮目录接入（2026-11-02）

- v0.2 的三个接口直接由 `burncloud-server` 承载；业务仅调整现有服务端与客户端，不新增 crate、进程、端口、状态数据库或独立页面。外部源目录不修改。
- 原弹层展示 18 个预置项与绑定资源；非空搜索使用 NDJSON 累计快照，无分页或二级版本列表。搜索并发 ModelScope/hf-mirror，国内站点超时才回退一次 Hugging Face，保留来源优先级去重规则。
- 状态一次返回完整资源快照；资源 GET 200 才显示下载入口。当前按未接入本地下载状态处理，不伪造可用或启用中状态。
- 下载确认直接调用既有 `accept_catalog`，传入空工件列表，不请求工件接口。既有模拟检测完成后明确提示缺少工件解析与部署；底层文件下载和校验代码保留，不假报 Ready 或启动推理。
- 主服务地址优先读取 `BURNCLOUD_SERVER_URL`，否则跟随 `HOST`、`PORT`，通配监听地址换成本机回环地址；缺省为 `127.0.0.1:3000`。客户端超时 45 秒，上游搜索 8 秒，资源探测 10 秒。
- 关键词或选项变更会取消旧请求，弹层卸载取消浏览任务；流式来源替换保持行标识，但废弃旧状态并重新查询。错误、截断流可重试，不回退模拟目录。
- 原五方法后端契约和工件初始化状态机保留。后文完整部署流程与历史验收仅描述既有工件能力或过往版本，不表示当前目录选择已能部署；当前 HTTP 契约以本节和接口文档 1.1 节为准。

## 第一轮保守清理（2026-11-04）

- 正式目录只保留 PickerState 一套搜索状态；ChatState 的旧查询、十项截断与展开全部方法及字段已移除。五方法后端、BuyerChat、模拟硬件与底层文件下载能力不裁剪。

- 清理没有生产使用者的旧选择器样式，不改变有效控件及 BuyerChat 的样式；当前入口不具备真实下载与部署的事实在界面、文档与组件测试中保持一致。
- 详细本地接口文档仍受现有 Git 忽略规则管理；README 的公开契约入口指向已跟踪的源码与主服务说明。本轮不调整上游结构门禁，也不声称已完成真实模型或原生窗口验收。

# 第一章：项目背景与目标

## 1.1 项目背景

根路径与首页别名均使用独立的 ChatHome，买方、供应方和管理员工作台保持原有路由。
沿用此前已完成的搜索与对话布局和正常流程文案，本轮把页面固定数据与计时推进迁移到可替换的类型化 Rust 接口；默认仍为本地替身，不接入 Ollama 或真实部署链路。

## 1.2 目标

仅使用输入框旁的模型搜索选择器和聊天消息区的流程卡片，完成：

当前目录：关键词搜索 → 结果预览与一次状态查询 → 确认选择 → 模拟硬件检测 → 明确提示缺少工件解析与部署。

既有有效工件的后端流程仍保留：检测 → 量化选择 → 下载 → 校验 → 部署 → 健康检查 → 上报 → 生成；真实目录没有工件凭据，不能进入该后续流程。

## 1.3 当前实现与边界

- 目录信息真实查询；目录检测卡片明确说明硬件数据仍为模拟，防止把资源网页可访问误解为真实部署完成。
- 目录名称与版本经 CatalogClient 查询；硬件与后续工件能力仍经 ChatBackend，默认 LocalBackend 为本地替身。
- 目录查询与资源网址可达性通过主服务内的模型选择模块真实联网；不进行真实硬件检测、文件下载、安装、健康检查或状态上报。
- 不增加服务、数据库、持久化、系统权限、独立下载页、硬件设置页或运行时适配层。
- Windows、macOS、Linux 共用一套界面和状态逻辑；三平台夹具通过不能视为真实硬件兼容性通过。
- 保留会话管理、推理强度、消息复制、思考过程、流式回复和停止生成。

# 第二章：参考界面分析

## 2.1 页面结构

左侧为会话栏，右侧为消息滚动区及固定 Composer。所有新增能力都放在模型弹层或流程卡片内。
不新增顶部工具栏、二级模型切换页、温度设置或语言选择器。

## 2.2 模型选择浮层

模型入口直接打开带搜索框的弹层；推理强度保留在弹层底部。
预置与搜索共用原弹层，结果区内部滚动，不提供分页或二级版本页面。

## 2.3 消息区域

普通用户、助手消息保持原展示方式。初始化流程使用 System 消息中的结构化卡片；各阶段更新同一条消息。
关闭后保留模型名称和结果摘要，不删除历史记录。若模型已在另一会话就绪，旧等待/失败卡片会提示已就绪并说明其为先前记录，不再展示下载或重试入口。

## 2.4 输入区与窄窗口

未选择模型也可以编辑草稿。点击发送会打开模型搜索并保留草稿。
初始化运行、等待选择版本和生成期间禁用输入；输入框不再附带演示范围提示。
模型弹层向输入框上方展开，宽度不超过视口；窄窗口下硬件信息和版本要求允许换行。

# 第三章：目标功能定义

## 3.1 初始状态

一个空白会话，不默认选模型。模型弹层加载并展示 v0.2 的 18 个预置项；旧本地 14 项目录不再作为正式入口。固定名称既不表示安装完成，也不保证资源可达。

## 3.2 搜索与选择

- 搜索与刷新沿用主服务的累计快照及顺序；清空恢复 18 项预置。部分来源失败不掩盖成功结果，上游错误记入服务日志；整体失败可重试，不回退模拟目录。
- 每项直接绑定来源、仓库和修订号；预览与关闭都不提交。流式快照替换而非追加，选中资源改变后重新查询状态。
- 只请求一次状态接口；服务端 GET 200 显示下载，其余结果显示开发中。当前不接真实本地状态；客户端仍识别四态，但 `available` 不能替代有效运行凭据。
- 只有确认才修改模型；草稿保留，未知工件不能标记 Ready，也不能通过发送或重试绕过能力缺失。

## 3.3 键盘交互

| 操作 | 行为 |
|---|---|
| 消息框 Enter | 发送；无模型时展开搜索 |
| Shift + Enter | 换行 |
| Ctrl/Cmd + N | 空闲时新建会话 |
| Esc | 关闭模型弹层并返回模型入口焦点 |
| 搜索框 Enter | 选择第一条可见结果，无结果时无操作 |
| 搜索框向下键 | 聚焦第一条结果 |
| 结果列表上下键 | 在当前可见结果间循环 |
| 结果按钮 Enter / Space | 选择当前结果 |
| Tab | 依次访问弹层内控制项 |

## 3.4 回复边界

只有模型就绪后才调用 generate，输入包含模型版本、实际用户/助手历史和推理强度，排除初始化 System 卡片。正文与思考分别通过类型化增量返回，指标可以为 None。错误显示在原助手消息中，保留已收到内容；停止生成销毁对应 future 并使请求编号失效。默认替身仍返回固定说明与固定指标，不代表真实推理、吞吐或费用。

# 第四章：整体架构设计

## 4.1 模块职责

实现集中于 E:\project\burncloud-one\crates\interfaces\client\src\domains\chat：

| 模块 | 职责 |
|---|---|
| catalog / selector | 主服务 HTTP 适配、累计目录快照与资源预览；目录请求随弹层卸载取消 |
| backend | ChatBackend 异步边界及 LocalBackend；固定目录、三平台硬件、占位路径、摘要、回复、指标及能力调用延迟只在这里生成 |
| model | 可持有的输入/输出契约、结构化错误、类型化事件、原有阶段枚举、消息与纯资源比较 |
| state | 模型确认、初始化和生成的编号与结果校验，会话管理、单任务流程、就绪记录、草稿恢复与续聊；不执行 I/O，也不重复维护目录搜索状态 |
| page | Dioxus 组件、调用接口、展示返回值、焦点/滚动与任务生命周期；不以计时判定成功 |
| tests / backend_tests / ui_tests / local_backend_tests / selector_tests / state_test_support | 独立测试与夹具文件；按实际职责覆盖后端契约、选择器和工件状态，不为测试保留生产旧搜索逻辑 |

样式沿用共享 UI 的 chat- 前缀；不修改 BuyerChat、模型市场或其他业务页面。

## 4.2 可见性与接口清单

唯一对外页面接口仍为 ChatHome() -> Element，签名不变，保留中文 doc-comment 与编译型 doc-test。
以下是明确允许聊天模块内部 pub(super) 的协作契约，不是 crate 对外 API：

- CatalogClient、CatalogPage<T>、CatalogModel、CatalogVersion、CatalogSelection、VersionStatus、CatalogPicker 及其共享字段与方法，详细清单见接口文档 1.1 节。
- ChatBackend、BackendFuture<T>、Callback<T>、LocalBackend 和组件树注入包装 BackendHandle。
- ChatModel、ModelVariant、Hardware、Gpu、Platform、InitializationRequest、PreparedModel、GenerationRequest、HistoryMessage、InferenceMetrics。
- HardwareEvent、PreparationEvent、GenerationEvent、ChatError、ErrorKind、Operation；沿用 PreparationStage，不引入另一套状态机。
- Preparation、ChatMessage、ChatConversation、GenerationPlan、ChatAction、ReasoningEffort 及原有状态读写方法。
- ChatState 的 begin_selection/finish_selection、hardware_event/finish_hardware、initialization_request、preparation_event/finish_preparation、generation_event/complete_generation 等结果入口；旧搜索入口不再保留。
- 纯比较 fits/shortfall、凭据校验 is_valid/valid_digest、字节展示 gib/resource_label 以及卡片进度、版本访问器。

ChatState 成员全部私有；本地目录构造、设备夹具、路径构造、除 CatalogPicker 外的页面子组件、调用调度和辅助函数均私有。固定摘要与回复片段只供聊天模块后端和独立测试使用。仅测试构建在独立文件明确提供 `pub(in crate::domains::chat) ChatState::set_test_models`，用于受控目录快照；生产构建不包含此方法。

## 4.3 五个异步操作

标准库 Pin<Box<dyn Future<Output = Result<T, ChatError>>>> 与 Box<dyn FnMut(Event)> 构成边界，无新增依赖。future 不要求 Send，适用于当前 Dioxus 单线程组件树；借用/回调不可跨线程擅自使用。取消通过 drop future 完成。

| 操作 | 输入 | 回调 | 最终结果 |
|---|---|---|---|
| search | String 关键词，允许空输入 | 无 | Vec<ChatModel> 或错误 |
| model_status | String 模型 ID | 无 | Vec<PreparedModel>，只代表本客户端可用版本；空列表表示未提供就绪版本 |
| detect_hardware | 无设备参数 | Cpu/Gpus/Memory/Disk 已完成项 | Hardware 或错误，必须与已报告项一致 |
| initialize | run_id、ChatModel 与用户确认的 ModelVariant 快照 | DownloadProgress、Downloaded、Verified、PackageLoaded、Deployed、Healthy、Reported | PreparedModel 或错误 |
| generate | PreparedModel、Vec<HistoryMessage>、ReasoningEffort | Content/Thinking 增量 | Option<InferenceMetrics> 或错误 |

后端由 ChatHome 的组件树上下文持有一个 Rc 实例；测试在根上下文注入相同契约，不建立全局服务注册器。所有能力调用任务由 ChatHome scope 持有，不能随模型选项卸载而取消。生成显式停止立即销毁任务；初始化协议错误进入终态后也取消仍在等待的后端任务。页面卸载释放其任务。

# 第六章：数据结构设计

## 6.1 模型与工件身份

ChatModel 使用独立 String id/name/description、Option<String> updated_at、Vec<ModelVariant> 与 Option<CatalogSelection>。真实目录快照完整保存来源与修订号，未经工件解析时 variants 为空。更新时间约定为可按字典顺序比较的标准化 ISO 日期/时间；本地目录使用 YYYY-MM-DD，不以创建时间替代更新时间。
版本包含 id、quantization、runtime、artifact_source、expected_sha256 和 u64 字节单位的 ram_bytes/vram_bytes/disk_bytes。
就绪身份绑定模型 ID、版本及工件摘要；当前实现同时比较完整版本快照，目录工件发生变化不能复用旧版本。

## 6.2 硬件与资源匹配

Hardware 包含可选平台、CPU、GPU 列表、内存和磁盘；Gpu 包含名称和 Option<u64> 可用显存。
未知资源不视为充足。已知无 GPU 时显存为零；多卡只取已知的单卡最大可用显存，不相加。资源相等满足要求，直接比较三个字节量，不评分、不推荐。
界面按 1024³ 字节转换 GiB，未知项显示“未知”；不足原因列出要求、可用量和差额。

默认替身按桌面编译平台选择三平台固定设备，Web/LiveView 固定使用 Windows 样例，不探测服务器或浏览器设备。默认可用内存 24 GiB、单卡显存 8 GiB、磁盘 128 GiB。路径分别采用 C:\BurnCloud\models\、/Users/user/BurnCloud/models/ 或 /home/user/BurnCloud/models/；这些字符串不对应实际落盘承诺。

## 6.3 消息、会话和准备结果

ChatMessage 保留角色、正文、可选思考、流式状态、复制状态、可选指标、可选结构化错误与可选 Preparation。初始化只更新一条 System 卡片，不进入推理历史。
PreparedModel 包含模型与版本快照、实际校验摘要和非空且不含 NUL 的本地路径；失败只返回 ChatError，不携带成功路径。
ChatConversation 与就绪凭据仅在当前客户端实例内存中共享，不持久化。

## 6.4 结构化错误

ChatError 统一携带 kind、operation、reason。ErrorKind 包括 InvalidParameter、NotFound、NotConnected、InsufficientResources、VerificationFailed、Timeout、ExecutionFailed 与 InvalidResult。
Operation 标明 Search、Status、Hardware、Initialize(现有阶段) 或 Generate。参数/来源错误由后端返回；乱序、矛盾或提前成功由状态边界转换为接口结果错误。不增加自动重试或通用超时调度器。

# 第七章：状态与交互流程

## 7.1 初始化阶段与完成证据

| 当前阶段 | 唯一允许的前进条件 |
|---|---|
| AwaitingStart | 点击下载或发送消息，创建新 run_id，调用检测 |
| Detecting | 接收已完成检测项；最终 Hardware 返回并通过一致性检查后才比较资源 |
| SelectingVariant | 停止调用后端，等待用户选择满足资源要求的版本；此时可关闭恢复草稿 |
| Downloading | 已完成字节数不得倒退或超过总量；已知总量不得中途改变。只有 Downloaded 才进入校验 |
| Verifying | Verified 的预期摘要等于版本摘要、本地摘要等于预期，摘要为有效 SHA-256，路径有效 |
| LoadingPackage | 收到 PackageLoaded |
| Deploying | 收到 Deployed |
| HealthChecking | 收到 Healthy |
| Reporting | 收到 Reported 后仍等待最终返回；最终模型、版本、摘要、路径必须与事件一致 |
| Ready | 仅上述证据全部成立后记录就绪；有待发送消息时续聊一次 |
| Failed | 保留结构化错误，清空成功路径、恢复草稿，不生成回复 |
| Cancelled | 关闭等待阶段，折叠保留摘要并恢复草稿 |

未知下载总量时显示“进行中”和不定进度条，不编造百分比。100% 不自动证明下载完成、摘要正确或部署成功。
阶段顺序以类型化事件为准；事件去重不重复产生副作用，跳阶段、异常进度、矛盾硬件、缺失摘要、空路径、提前返回成功或错版本均失败，绝不自动补齐。

流程：选择 → 状态查询 → 用户发送/下载 → 硬件结果 → 资源匹配 → 用户确认版本 → 下载完成 → 校验 → 加载 → 部署 → 健康 → 上报事件 → 最终准备结果一致 → 就绪 → 可选续聊。

## 7.2 草稿、请求编号与重试

- 无模型发送只打开搜索并保留草稿；状态查询未完成/失败时不能发送或初始化。
- 初始化发送先暂存草稿，不写用户历史；完成后仅一次写入实际用户消息并调用生成。
- 初始化同时最多一个任务；运行或等待版本时锁定模型与会话，重复启动无效。
- 每次重试分配新 run_id，从检测开始，清除旧进度、硬件、版本、摘要、路径与错误。
- 只有当前会话、当前模型最后一张卡片的当前任务可接收回调；终态和旧任务回调忽略。
- 失败恢复原稿。仅点击“重试”不自动发送已恢复但未再次发送的草稿。
- 等待或终态可关闭，运行中不提供关闭；保留历史摘要，不伪装为取消真实部署。

## 7.3 搜索、选择与会话共享

搜索与选择分别编号；错误与成功都必须属于最新请求。选中模型不会被搜索结果或旧选择回调隐式替换。
预置就绪凭据由 model_status 返回；本次初始化完成的凭据在客户端状态中追加并跨会话复用，不把市场在线状态作为本机就绪。
新建会话保留选中模型；删除最后一会话后创建空白会话。状态查询期间拒绝会话切换/删除，避免通过换会话绕过发送禁用。

## 7.4 生成与取消

每次生成传入真实用户/助手历史与推理强度，排除卡片，待发送用户消息只追加一次。
正文与思考增量分别累积；没有指标时不显示伪造指标，但复制操作仍可使用。生成错误留在原助手消息内，不追加假回复。
停止先使生成编号失效，再 cancel 对应 Dioxus Task，drop 后端 future。保留已接收内容，不响应停止后迟到的增量或结果。

# 第九章：模型选择器设计

## 9.1 当前来源

`CatalogPicker` 通过 `CatalogClient` 查询主服务三个模型选择接口。空查询显示 18 个预置项，非空查询逐行消费 NDJSON 累计快照，不追加分页，也不使用旧本地目录的十项上限。

## 9.2 真实能力边界

目录三个端点由主服务提供，但 `resource_url` 是仓库页面，不是可部署的模型文件。版本状态 `available` 不是 `PreparedModel`；未提供运行时、摘要、资源要求和本地路径的外部版本不会进入生成。

默认硬件后端仍为本地替身。检测卡片明确标注模拟，检测完成后提示尚未接入工件解析与部署；不增加真实下载、安装或推理能力。其余五方法工件流程和校验规则保留。

# 第十章：错误处理与边界条件

- 空模型 ID、无效初始化快照、缺少用户消息等返回参数错误；未知模型返回未找到，非本地支持的版本/后端返回未接入。
- 搜索失败保留弹层并可重试；状态查询失败保留选中模型及草稿，禁止发送直到重试成功。
- 未选版本不调用 initialize；资源未知或不足不能强选版本。多 GPU 显存不相加。
- 错误进度、跳阶段、无效摘要/路径、提前成功、错版本或结果与回调不一致均不能标记就绪。
- 任一初始化失败恢复草稿、清空成功路径，不产生回复；终态、旧请求和重复成功不再次续聊。
- 后端可以返回 Timeout，但页面不额外创建超时调度器或自动重试。
- 生成失败保留原消息内容与原因，不伪造回复或指标；停止任务后迟到事件无副作用。
- 剪贴板、焦点和滚动脚本错误保留日志。不使用 unsafe，不在外部输入上 unwrap()/expect()。
