# 本机路由挂载复用当前实例的 Router 与存储

本轮本机模型挂载限定在当前 BurnCloud 实例内，复用既有 Router 和供给存储，不建立独立的本机路由表，也不增加跨机器注册、远程心跳上报或云端接入协议。
选择这一边界，是为了在保留 `LocalRouteAttacher` 已有挂载契约的前提下，以尽可能少的工作区与代码补齐可用性管理，而不是再维护一套注册与调度体系。
该决定不取消心跳、模型能力、地址、容量和运行状态要求；它们仍须在实例内形成可验证的持续可用性闭环，具体语义另行确认。

## 首版生产挂载触发边界

2026-11-04 已确认：首版由 Server 启动配置提供已真实就绪的本机端点清单，每项仅表达现有 model 与 base_url；Server 校验端点和模型别名后调用既有 LocalRouteAttacher，并在自身生命周期中持续管理挂载。选择这一边界，是为了复用现有挂载契约并尽量把改动集中在 Router 与 Server，而不为本功能扩展客户端事件链路和模型部署系统。

首版暂不接入客户端运行中新就绪模型的自动挂载，不新增客户端 UI、公开注册 HTTP API、模型安装器或 workspace 成员。配置清单不成为第二份路由事实来源；正式挂载仍复用现有供给存储。模型列表成功不能代替真实就绪和真实推理验收。

生产触发范围、下述端点协议、模型字符串合法域、启动处理、挂载目标身份边界、重复操作结果及持久化失败处理已确认，但不表示已经实现。2026-11-05 又确认了启动配置名称与格式、首检复探时序和保守重启规则，见下一节；已挂载节点的心跳有效期、恢复阈值及运行故障分类仍待确认。

### 本机端点协议与地址约定

2026-11-04 已确认：为保持现有 model、base_url 输入并减少首版接线改动，仅接入无需上游 API Key 的本机 OpenAI 兼容服务。base_url 使用 HTTP(S) 回环 IP 的服务根地址，不带 /v1 等路径前缀、用户名密码、查询参数或片段；不接受域名和非回环地址，末尾斜线可统一去除，本机端点探测与推理均不跟随重定向。

存活探测请求 /v1/models 并精确匹配 data[].id 与配置 model；本机聊天推理最终请求同一服务的 /v1/chat/completions，不自动改写模型别名或扩大注册能力。探测成功不等于真实推理成功；不能因为模型列表可用就忽略实际推理故障。

不新增上游凭证输入，也不取消 BurnCloud 自身的认证、授权和计费校验；不借本机路径对齐修改既有非本机供给的地址及鉴权语义。启动处理按下节约定；故障阈值和已挂载节点的恢复规则仍待确认。

### 启动校验与首检失败处理

2026-11-04 已确认：未配置本机挂载或配置为空清单时，Server 正常启动且不创建本机挂载；配置格式、必填字段或地址不合法时明确报错并拒绝启动，先完成整份配置校验，再执行挂载，避免只处理部分配置。

合法清单中的单个端点首检失败时，该项不挂载、不接请求并记录失败，不阻止 Server 和其他可用供给继续服务；由同一管理任务继续探测，检查通过后再尝试首次挂载。这样区分部署配置错误与单节点暂时不可用，避免一个端点故障拖垮其他供给。

上述重试仅适用于启动清单中尚未成功挂载且首检失败的项，不自动解除隔离、不扫描运行中新端点。首次时序与重启按下一节已确认规则执行；已挂载节点的故障恢复仍待集中评审。端点首检复探与 attach 持久化失败分开处理，后者按下文已确认 D05 停止该项自动挂载，不能借探测循环重试写入；重复操作结果另见挂载管理操作结果。

## 启动配置、首次探测与保守重启

2026-11-05 已确认：使用环境变量 `BURNCLOUD_LOCAL_ROUTE_ATTACHMENTS` 提供 JSON 数组，每项仅含 model、base_url；先校验整份清单，再进行任何端点探测或挂载。首次立即探测，首检失败后每 5 秒复探，单次超时 2 秒；attach 失败即停止该项自动挂载，不重试数据库写入。这次确认只确定首次挂载阶段的 5 秒／2 秒，不自动批准运行中心跳的 15 秒有效期或连续两次成功恢复。

停止时终止管理任务，禁止迟到结果发布挂载。重启不自动收养、删除或恢复旧挂载，持久化残留继续禁派；调用方核对并显式 detach 后才能重新挂载，无残留的配置项正常处理。清理残留不意味着本次已失败的启动配置项会自动重试，仍遵守 D05。选择该方案是为了避免增加持久化恢复协议，并防止旧隔离或提交结果不明的供给被误放行；代价是有残留时重启不会自动恢复接单，需要人工介入。

这里的显式 detach 沿用 Rust 管理接口，不表示首版新增了 HTTP／CLI 管理入口。它不重新授予旧 ID 许可，也不允许旧实例的探测结果修改新实例。具体资源所有权与退出顺序属于后续技术设计，不以终止探测任务代替 Router 的同步禁派。

## 挂载目标与身份边界

2026-11-04 已确认 D05 的身份边界：当前实例内，以精确匹配的模型名和规范化服务根地址共同识别挂载目标。地址按协议、回环 IP 与有效端口比较，末尾斜线及显式／省略默认端口不区分身份；不同回环 IP 不合并，不自动改写模型大小写或别名。具体挂载仍由 LocalRouteAttachmentId 指向。

同一目标最多保留一个未摘除挂载，并发或重复 attach 不能重复创建供给、增加额度或解除停派；故障、隔离不释放身份。同模型不同地址、同地址不同模型均是不同目标，可以分别挂载；容量仍按挂载 ID 独立计量，不增加端点级共享上限。不新增原地更新接口；替换模型或地址时先 detach 旧挂载，再 attach 新挂载，不改写旧 ID 的目标。

选择目标对而不是单独模型名，是为了允许同模型多端点参与调度，同时避免同一目标被重复登记而扩容；选择每挂载容量而非端点共享容量，是为了保留已确认的最小容量模型，代价是不提供同一端点全部模型的合计并发保证。本节已确认身份边界，但不表示已实现去重；持久化失败处理见下文已确认 D05，重启残留按上文已确认 D06 保守规则处理。

## 挂载管理操作结果

2026-11-05 已确认：挂载管理操作必须围绕本机挂载归属和既有生命周期状态返回可观察结果，不用重复注册恢复隔离，也不以数据库异常冒充目标不存在。

- 同一目标重复 attach 时，若既有挂载仍健康、心跳有效且未隔离，返回既有挂载 ID；容量已满不改变这一身份结果，也不增加供给、容量、心跳或健康状态。
- 同一目标已有隔离、已知模型故障或失效心跳时，重复 attach 返回 AttachFailed，保留原状态。
- 对仍存在的本机挂载重复 quarantine 返回成功并保持隔离；对正数但不存在或已摘除的 ID 返回 DetachFailed。
- 对正数但不存在或已摘除的 ID detach 返回成功；对现存非本机 ID 或小于等于 0 的 ID，quarantine 与 detach 均返回 DetachFailed，不修改其他供给。
- 数据库查询、写入、权限或事务失败必须返回相应错误，不能按“不存在”成功处理。detach 后重新挂载同一目标使用实际新生成的 ID，旧 ID 不影响新挂载；模型或地址替换仍先 detach 再 attach。

本节不改变 LocalRouteAttachmentError 仅包含 AttachFailed 与 DetachFailed 的公共契约；持久化失败处理按下节执行。

## attach 持久化失败处理

2026-11-05 已确认 D05 的最后一组规则：首版不新增数据库写入自动重试机制，以减少恢复状态分支，并避免在提交结果不确定时自动重试或误放行新挂载。

- attach 持久化失败返回 AttachFailed，不吞错、不在接口内部循环重试。
- 启动管理任务记录该项错误并停止该配置项的自动挂载尝试，不影响其他正常供给；数据库恢复后，该失败项不会自行重新挂载。
- 提交结果不确定时，不把该新挂载视为成功，也不授予派发许可；调用方核对后显式重试，仍遵守已确认的目标身份与重复操作规则。
- 端点首检失败后继续探测的规则不变，但不能把持久化失败当成首检失败，借探测循环重新触发自动挂载。

选择这一最小处理方式的代价是数据库恢复后仍需调用方介入核对并显式重试。D05 据此完成决策收敛；它本身不证明实现或真实验收。D06 已由上文独立确认的保守重启规则约束，不通过 D05 推导自动恢复。

## 模型字符串合法域

2026-11-05 已确认：本机挂载的 model 作为单一、原样的模型别名贯穿能力登记、Router 匹配和端点探测。入口拒绝空串、首尾 Unicode 空白、英文逗号和控制字符；保留大小写与 Unicode，允许内部普通空格，不额外禁止冒号；长度按 Unicode 标量值计不超过 34，不按字节或视觉字形计数。该上限来自当前适配器 16 字符名称前缀与 PostgreSQL 50 字符名称列的联合兼容边界，非法输入使用既有 AttachFailed，不改变非本机供给的多模型字段语义。

保留原名而非自动 trim、拆分或改大小写，是为了让一个挂载只声明一个精确模型能力。Router 不得对 JSON 模型名统一按冒号截断，同时保留 Gemini 路径方法后缀语义。Ticket 01 已有对应修复与受控测试，执行证据以 0001 任务报告为准；这不代表真实模型验收已经完成。

## 路由策略配置

均衡、稳定优先和价格优先是三种独立策略，复用既有 `SCHEDULER_POLICIES` 按用户组配置的入口；每次请求继承所属用户组的一种策略，未配置时默认均衡。
首版不新增客户端策略切换界面或请求参数，保持 `LocalRouteAttachment { model, base_url }` 的输入契约不变，以避免为了策略选择扩展客户端与请求协议。
模型匹配、节点健康、心跳有效和容量可用是所有策略共同的准入条件，任何策略均不能绕过；三种策略的候选筛选与统一选择逻辑按下文约定。具体价格比较口径以及心跳探测阈值、超时与恢复规则仍待确认。

### 三种策略的统一选择逻辑

三种策略均在最高可用管理员优先级档内先筛选候选集合，再共用一个内部权重选择函数：仅一个候选时直接选择，存在多个候选时按管理员 `weight` 加权随机选择，权重相同则等概率。

- 均衡：该档内全部满足共同准入条件的节点参与选择。
- 稳定优先：仅该档内现有健康评分最高的节点参与选择；最高分并列时按统一权重逻辑分摊。
- 价格优先：仅该档内具有最低有效、可比较报价的节点参与选择；最低价并列时按统一权重逻辑分摊。具体价格比较口径另行确认。

稳定优先复用既有成功／失败记录、延迟等运行健康指标，不新增评分系统；它评价服务运行表现，不评价模型回答质量。
均衡是按权重进行概率分摊，不保证逐次交替或短期次数严格符合比例，也不额外维护轮询进度。三种策略仅筛选条件不同，不各自复制一套权重选择算法。

### 价格来源与范围

首版价格优先复用既有按模型与 region 查询的有效报价，不新增按挂载 ID 或节点单独报价的表或配置，也不向 `LocalRouteAttachment` 添加价格字段，以避免为本机挂载扩展计费模型。
候选存在有效、可比较的价格差异时按价格优先选择；并列最低价时按下述权重随机分摊规则选择。价格缺失不视为零价格，本机模型不默认免费，也不绕过现有计费校验。
价格优先的同价处理已确认为：在最高可用管理员优先级档内，对并列最低价的可调度候选按管理员 `weight` 加权随机选择；权重相同则等概率。容量已满或不满足其他准入条件的候选不参与选择，缺失报价不能当作同价或免费。
价格优先的同价分配与均衡、稳定优先的并列候选处理共用上文的权重选择逻辑，不另建独立算法。
仅凭现有报价无法区分同模型、同 region 下不同节点的运行成本；候选均使用相同报价时，价格优先可能与均衡策略表现一致，不能据此宣称选中了实际运行成本最低的机器。
本节确认报价来源与范围，具体价格比较口径仍待确认；管理员优先级与会话亲和按下文约定。

### 管理员优先级降档

在满足已确认共同准入条件的候选中，保留管理员优先级档位，优先使用最高可用档位；高优先级节点全部不可用时，允许降到下一档，而不是在仍有低优先级可用节点时直接报告无可用节点。
降档不得放宽模型匹配、节点健康、心跳有效或容量可用的准入条件。三种策略在最高可用档位内按上文规则筛选和选择候选，会话亲和按下文约定。

### 会话亲和与旧策略兼容

均衡、稳定优先和价格优先三种新策略不再由会话亲和重排候选或替换所选目标，避免会话固定回到原节点而破坏均衡或择优结果；价格相同时仍按已确认的同价分摊规则选择。
不全局删除既有会话亲和能力，显式配置的旧策略保留原有亲和选择行为。未配置策略时仍按前述默认均衡处理，不视为显式选择旧策略。
保留旧策略的亲和行为不意味着允许本机挂载绕过模型、健康、心跳或容量准入条件；不可用挂载不能因亲和而继续接单。

## 容量口径

首版容量按每个 `LocalRouteAttachmentId` 的并发请求槽计算：可用槽位等于该挂载的最大并发数减去当前在途请求数，不以 CPU、内存、显存剩余量或 RPM/TPM 速率预算替代。
容量为零时，不向该挂载分配新请求；流式响应包含整个响应流的处理过程，不能在收到响应头后提前释放槽位。
并发上限由一个 Router 启动配置项统一指定，默认每个本机挂载为 1；统一的是上限值，各挂载 ID 仍独立占用和释放自己的槽位。
修改上限后须重启生效；首版不支持按模型分别覆盖或运行时热更新，也不向 `LocalRouteAttachment { model, base_url }` 添加容量字段。
该配置表示允许接收请求的并发上限，不代表自动探测得到的硬件容量。

## 派发许可、在途请求与容量拒绝

2026-11-04 已确认 D03：派发前的可用性复查与并发占槽共同决定是否授予一次派发许可，候选列表、排序和亲和不能代替许可。隔离或摘除成功后不再授予新许可，此前已获许可的一次尝试不主动截断，仍受正常完成、超时、取消或上游失败约束。停派以许可授予而非网络第一字节为界，旧许可对应的尝试可能在隔离返回后才实际发送；一个许可只用于一次尝试，重试或换目标须重新准入。

流式响应在整个处理生命周期内占槽，不因收到响应头、返回流对象或前端断开就提前释放；后台仍处理上游流时继续占槽，实际处理结束后释放。容量耗尽只跳过、不记模型故障、不隔离、不删除；无其他可用候选时返回错误，不新建等待队列或等待容量恢复的循环。允许在既有请求重试预算内尝试其他合格候选。

选择这一边界，是为了可靠阻止新的分配，同时避免为隔离功能增加主动终止在途推理的机制；它不承诺已故障模型一定完成请求，也不承诺隔离返回后绝无任何网络发送。

### 请求错误响应的兼容边界

- 已识别本机准入拒绝、候选耗尽且未实际尝试上游时，复用 HTTP 503：error.type 为 service_unavailable、error.code 为 no_available_channels、rejected_by 为 scheduler；沿用 X-Rejected-By: scheduler 与 Retry-After: 60。60 是既有退避提示，不是心跳阈值或恢复承诺。
- 供给查询本身无匹配路由且未识别本机准入拒绝时，保留既有 404／no_available_channel 或准备中响应。隔离、摘除后的新查询也可能进入此路径，不为统一状态码新增已删除路由记录或第二套路由表。
- 已实际尝试上游后全部失败或请求重试预算到期，保留既有 502／all_upstreams_failed 或 504／retry_deadline_exceeded，不用后来发生的本机准入拒绝掩盖上游失败；已开始的流式响应不能再改写 HTTP 状态。
- 既有认证、授权、计费及纯速率预算拒绝各自保持原处理。挂载管理接口仍只使用 AttachFailed／DetachFailed 两个错误变体；价格不可比较时的响应仍属 D04，未随本次决定批准。

## 心跳与运行状态的职责

本机挂载管理任务随当前 Server 生命周期运行，负责持续探测已挂载的真实模型端点，并更新各挂载的心跳与运行状态；不以聊天界面是否在线作为节点存活依据。
健康判断必须有真实模型端点探测作为依据，不能只定时刷新时间戳，也不能把 Server 通用 `/health` 的固定成功响应当作某个模型健康的证明。
即使挂载管理任务意外停止更新，Router 也必须能够根据心跳超时停止向相关挂载分配新请求。
本节确认职责归属与下述健康证据；首次挂载阶段的探测间隔与单次超时已在上文确认，已挂载节点的探测时序、故障判定阈值、心跳超时阈值与故障恢复规则仍待确认。

### 健康证据

首版采用轻量端点探测与真实推理结果反馈，不定时额外发送测试推理请求。
轻量探测直接访问挂载地址对应的模型服务，并核对挂载模型别名仍在该服务提供的模型列表中。
连接失败、超时、模型消失，以及真实推理请求暴露的模型故障，都参与停止派发的判断；具体故障阈值与恢复条件仍待确认。
模型列表查询成功只证明端点可达、模型声明存在，不等同于已经验证推理成功。

## 待最终确认的运行规则草案

以下为访谈中的推荐方案，待最终设计确认后再转为正式约定；不表示已实现或已通过真实模型验证。

### 故障停派阈值

建议每 5 秒进行一次轻量探测，单次超时 2 秒；一次明确的连接失败、超时或模型别名消失即停止新分配。真实推理暴露明确的模型或端点故障时同样停派，用户请求参数错误不计为模型故障。
建议连续 15 秒没有有效心跳时，在请求派发准入处拒绝该挂载，不依赖后台清理任务。此超时是管理任务失联的兜底，不是已发现故障后继续派发的宽限期。
以上时间值暂作为首版内部默认值，不增加配置项；“立即停派”指检测到故障之后，而非故障发生瞬间。

### 故障恢复与显式隔离

建议仅由轻量探测失败引起的临时不可用，在连续两次探测成功且模型别名仍存在后允许自动恢复；实际派发仍须满足全部准入条件。
真实推理暴露明确的模型故障时，不凭模型列表恢复正常自动恢复接单；由调用方重新确认模型就绪，清理旧挂载后通过既有 `attach` 重新挂载。
显式调用 `quarantine(id)` 成功后保持隔离，后台探测不得自动解除；同样通过清理旧挂载、确认就绪和重新挂载恢复，不新增解除隔离接口。
