# Bug #034 修复报告

## Bug 信息
*   **Bug 编号**: #034
*   **优先级**: P0 (阻塞构建)
*   **问题文件**: `src/main.rs`
*   **现象**: 代码中存在两个标记了 `#[tokio::main]` 的异步函数 `run_async_server()` 和 `run_async_cli()`，导致 `cargo build` 时出现编译错误 `duplicate #[the_fn]`。

## 根因分析
`#[tokio::main]` 宏会为其标记的函数创建一个新的 Tokio Runtime。当同一 crate 内存在两个这样的标记时，Rust 编译器会报错，因为通常只应有一个程序入口点。项目的实际入口是 `main()` 函数，但在处理 CLI 命令时，错误地依赖了另一个 `#[tokio::main]` 函数。

## 修复方案（单点最小改动）
1.  **移除 `run_async_cli` 上的 `#[tokio::main]` 宏**：将该函数还原为普通的 `async` 函数。
2.  **在 `main()` 中显式创建 Runtime**：修改 `main()` 函数中调用 `run_async_cli` 的逻辑，使用 `tokio::runtime::Runtime::new().unwrap().block_on(...)` 来手动管理 Runtime 的生命周期。

## 改动清单
**文件**: `src/main.rs`
1.  **L80**: 修改 CLI 调用方式
    *   **修改前**: `run_async_cli(&args[1..])?;`
    *   **修改后**: `tokio::runtime::Runtime::new()?.block_on(run_async_cli(&args[1..]))?;`
2.  **L168**: 移除宏属性
    *   **修改前**: `#[tokio::main]\nasync fn run_async_cli(args: &[String]) -> Result<()> {`
    *   **修改后**: `async fn run_async_cli(args: &[String]) -> Result<()> {`

## 验证结果
*   **`cargo check`**: ✅ 通过
