# 007 实现后台运行时健康监控

## 修改的信息

- 新增 `spawn_monitor`：仅接受首次健康状态 `Ready` 或 `Unhealthy`，创建可取消的后台任务并登记 PID、计划、状态和 generation。
- 新增 `monitor_runtime`：首次检查延迟 10 秒，此后按固定周期先查 PID，再用同一个 `ReadinessTarget` 查健康；状态未变化时不发布事件。
- 健康 `false` 保留运行进程并记为 `Unhealthy`；后续 `true` 可恢复 `Ready`。PID 退出发布 `Failed` 后结束，不重复停止已退出进程。
- PID/health 操作错误时清理进程并发布 `Failed`；状态变化事件重试耗尽时清理进程并返回 `EventPublishFailed`。监控任务错误由任务包装逻辑送入服务错误通道，通道关闭时记录错误日志。
- 使用全局 generation 防止过期监控任务修改新运行时状态；本地取消或 Node 关闭信号可终止等待、PID 查询和健康请求。

## 修改的文件与文件内位置

- `crates/platform/node/src/deployment/service.rs`：`DeploymentCoordinator.generation`、`DeploymentService::spawn_monitor`、`DeploymentService::monitor_runtime`、`report_monitor_failure` 与 `monitor_state_event`。
